# Story 1.3: Implement Temperature Telemetry Publishing

## Status
Draft

## Story
**As a** remote monitoring operator,  
**I want** regular temperature telemetry published via MQTT,  
**so that** I can monitor all sensor readings in real-time from any MQTT-enabled platform

## Acceptance Criteria
1. Temperature data published every 60 seconds to telemetry topic
2. Only configured points with bound sensors included in payload
3. Disabled points and unbound sensors excluded from telemetry
4. JSON payload matches specified format with point details
5. Delta updates published on significant changes (>0.5°C)
6. Messages logged to mqtt_log when history enabled
7. Telemetry can be temporarily set to 10s interval for testing
8. Message size optimized by excluding unused points

## Tasks / Subtasks
- [ ] Implement telemetry publishing (AC: 1, 2, 3)
  - [ ] Create publishTemperatureData() timer in main loop
  - [ ] Filter points by configuration status
  - [ ] Check sensor binding before including
  - [ ] Build JSON payload with active points only
  
- [ ] Create telemetry JSON formatter (AC: 4)
  - [ ] Include point ID, name, value, unit, status
  - [ ] Add sensor type and address
  - [ ] Include alarm state if active
  - [ ] Format timestamp in ISO8601
  
- [ ] Implement delta publishing (AC: 5)

## Dev Notes

### Architecture Context
- TemperatureManager maintains all sensor readings
- ConfigManager tracks point enable/disable status
- Each point can have DS18B20 or PT1000 sensor
- System supports up to 60 points (50 DS18B20 + 10 PT1000)

### JSON Payload Format
```json
{
  "timestamp": "2024-10-18T15:30:00Z",
  "deviceId": "ESP32-XXXX",
  "points": [
    {
      "id": 1,
      "name": "Tank 1",
      "value": 25.5,
      "unit": "C",
      "status": "normal",
      "sensorType": "DS18B20",
      "sensorAddress": "28:FF:64:1E:3C:D2:04:A8",
      "alarmState": null
    }
  ],
  "pointCount": 35,
  "uptime": 3600
}
```

### Performance Optimization
- Pre-allocate JSON buffer (4KB should suffice)
- Build array only with active points
- Use ArduinoJson streaming if needed
- Topic: tempcontroller/telemetry/temperature

### Delta Publishing Logic
- Maintain float previousValues[60] array
- Check each point: abs(current - previous) > 0.5
- Publish only changed points to telemetry/changes
- Include reason: "threshold" in delta messages

### Testing Approach
- Configure subset of points (e.g., 10)
- Use MQTT Explorer to monitor messages
- Verify excluded points don't appear
- Heat/cool sensor to test delta
- Check message size reduction
