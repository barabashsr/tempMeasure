# Story 1.2: Implement MQTT History Logging Framework

## Status
Draft

## Story
**As a** system administrator,  
**I want** comprehensive logging of all MQTT communications,  
**so that** I can audit system activity, troubleshoot issues, and maintain compliance records

## Acceptance Criteria
1. MQTT logging can be enabled/disabled via web interface checkbox
2. Log files created in CSV format: timestamp,direction,topic,size,status,priority,message_preview
3. Log files named mqtt_log_YYYY-MM-DD.csv on SD card
4. Automatic log rotation at midnight with configurable retention (1-30 days)
5. Three priority levels supported: NORMAL, HIGH (alarms), AUDIT (commands)
6. Logging integrated into existing LoggerManager
7. Settings added to settings-mqtt.html page
8. No performance impact when logging disabled

## Dev Notes

### Architecture Context
- LoggerManager already handles event logging to SD card
- Similar CSV format used for existing event logs
- SD card file system uses LittleFS
- ConfigAssist auto-generates form fields

### Implementation Details
- CSV headers: timestamp,direction,topic,size,status,priority,message_preview
- Direction: IN/OUT
- Status: OK/ERROR
- Priority: NORMAL/HIGH/AUDIT
- Message preview: First 100 chars, escape special characters
- File location: /logs/mqtt/mqtt_log_YYYY-MM-DD.csv

### Performance Considerations
- Only write to SD when logging enabled
- Buffer writes if possible
- Check free space before writing
- Use efficient string formatting

### Web UI Integration
- Section goes after existing MQTT connection settings
- Use ConfigAssist patterns for form generation
- Checkbox should show/hide retention days input
- Help icon with tooltip explaining feature

### Testing Standards
- Enable/disable via web interface
- Check file creation only when enabled
- Verify CSV format with header row
- Test midnight rotation (change system time)
- Fill retention period, verify old files deleted
- Monitor SD card write activity
